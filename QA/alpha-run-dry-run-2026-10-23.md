# Alpha run dry run, 2026-10-23

Full end-to-end dry run of the Fathom alpha-exit criteria with `pnpm alpha:run --dry-run`, on the recorded, scrubbed Fathom API fixture `examples/fathom-api-recorded.json`. No credentials, no network, no live API call. Run by Claude Code on Windows 11, Node v22.22.1, base commit `b2cbf2a` (origin/main) plus this branch's changes.

## What the dry run exercises

The same code path as Alexei's live run (`pnpm alpha:run`), with only the HTTP answer replaced:

1. `POST /v1/sources/fathom/sync` on the real router app, which calls `fetchFathomMeetings` and its schema checks. The recorded responder answers `GET https://api.fathom.ai/external/v1/meetings` with two pages (cursor pagination) and honours `created_after` and `created_before`. The window holds two meetings; only recording `900000001` is the target.
2. Quarantine preview into `data/quarantine/obsidian-inbox/`.
3. `POST /v1/proposals/:id/approve` and `/deliver` for the Obsidian proposal, writing to `data/quarantine/obsidian-approved/`.
4. Replay: the same sync again, then a second preview attempt.

A fetch guard wraps every request: anything not on `api.fathom.ai` is refused and counted, and transcript lines seen in Fathom responses are kept in memory for the A4 check. The responder rejects any key other than the dry-run placeholder, so a real key could not be used even if one were set.

## Findings from the M1 read of the synthetic output

1. **Doubled heading.** When Fathom's `default_summary.markdown_formatted` starts with `## Summary`, the approved note shows `## Summary` twice. Cosmetic. Owner: `packages/destination-obsidian`.
2. **Two proposal ids.** The quarantine preview's `proposal_id` is generated by the offline preview, not the router's proposal id that was approved. A reviewer matching the two files by id will not find a match. Matching by `source_meeting_id` works.
3. **Preview wording.** The preview says the source was "imported manually", which is inaccurate for the API path. Cosmetic.
4. **Repeat runs accumulate files.** In the API path the preview is rebuilt from router state, whose `created_at` is the router's receive time, so each run produces a new source hash and a new quarantine file. Within one run the replay is still refused. The checklist tells Alexei to clear old runs.

None of these blocks the alpha exit. They are listed in the PR as follow-ups.
